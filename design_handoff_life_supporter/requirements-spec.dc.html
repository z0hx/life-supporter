1. 概要と目的

life-supporter は、日常生活を支援する個人向けPWA。第1弾として「メモ(気になる店・場所・買い物リストの一元管理)」と「店頭での単価計算」の2機能を提供する。将来的に家計簿・リマインダー等の機能を追加し、生活全般をサポートするツールへ成長させる。

  • 対象デバイス:スマートフォン(390px基準)。店頭での片手操作を最優先。
  • ホーム画面から各機能へ遷移するハブ構成。将来機能の追加枠をホームに常設。
  • トーン:シンプル・実用重視。
  • ビジュアルデザイン(確定):案1c「やわらか実用」を採用。生成りの背景(#FAF6F0)×テラコッタのアクセント(#D97757)、丸ゴシック体(Zen Maru Gothic)、角丸の大きいカード、丸型チェックボックス。

2. 機能要件 — メモ

TVで見た行きたい店・場所、買い物リストなどを一元管理する。

  • 追加・完了・削除:1行入力で即追加。チェックで完了(取り消し線+リスト下部へ)。スワイプまたはメニューで削除。
  • カテゴリ:「買い物」「行きたい店」「場所」「その他」の既定4種+ユーザー追加可。各メモに1つ設定。
  • タグ:各メモに複数設定可(例:#TVで紹介 #週末)。入力時は既存タグからの選択+新規作成。
  • グルーピング表示:「カテゴリごと / タグごと / グループなし」を切り替え。タグごと表示では複数タグを持つメモは各グループに表示、タグなしは「タグなし」グループへ。グループは折りたたみ可。
  • ソート:「作成日時 / 更新日時 / 手動」を選択(新しい順・古い順)。手動はドラッグハンドル(⠿)による並べ替え。優先度「高」フラグは各グループ内で常に先頭。
  • グルーピング・ソートの選択状態は保持し、次回起動時も再現する。
  • 補足情報:任意でメモ本文・出典(例:TVで紹介)・追加日を保持。
  • 完了済みは30日後に自動アーカイブ(設定で変更可)。

3. 機能要件 — 単価計算

  • 入力:商品ごとに「価格(円)」「内容量」の2項目のみ。商品名は任意。数値キーパッドを自動表示。
  • 単位モード:100gあたり / 100mlあたり / 1個あたり / 1枚あたり を切り替え(比較中の全商品に適用)。
  • 比較・最安判定:2商品以上を並べて比較。入力と同時にリアルタイムで単価を計算し、最安の商品をハイライト+「◯% お得(差額 ¥x/単位)」を表示。商品は3つ以上追加可能。
  • 履歴:比較結果を任意の名前(例:トイレットペーパー)で保存。履歴一覧から再表示・再利用できる。
  • 計算式:単価 = 価格 ÷ 内容量 × 基準量。表示は小数第1位まで。

4. 画面構成

  • ホーム:あいさつ+日付/メモカード(未完了の先頭2〜3件プレビュー+件数)/単価計算カード(前回の比較結果)/「今後の機能」プレースホルダー/設定。
  • メモ一覧:グルーピング切替(カテゴリ/タグ/なし)+ソート切替(作成日時/更新日時/手動)のコントロール/グループ見出し(件数・折りたたみ)/メモリスト(チェック・タグ表示・優先度)/追加ボタン(FAB)。
  • メモ追加・編集(モーダル):タイトル/カテゴリ選択(1つ)/タグ入力(既存から選択+新規作成、複数可)/優先度/補足メモ/作成・更新日時の表示。
  • 単価計算:単位モード切替/商品カード(A, B, C…)/最安判定パネル/商品追加/保存・クリア。
  • 履歴一覧:保存名+日付のリスト。タップで比較内容を復元。
  • 設定:カテゴリ管理/アーカイブ設定/データのエクスポート(JSON・共有シート)・インポート・全削除/バックアップリマインド。

5. 非機能要件・PWA仕様

  • オフライン動作:Service Workerで全アセットをキャッシュ。店頭(電波が弱い環境)でも全機能が動作すること。
  • データ保存:端末ローカルのみ。サーバー不要・アカウント不要(詳細は6章)。
  • インストール:Web App Manifest(name: life-supporter、standalone表示、テーマカラー、192/512pxアイコン)。ホーム画面追加を促すバナー。
  • 性能:起動から入力可能まで1秒以内。単価計算は入力毎に即時反映。
  • 操作性:タップ領域は44px以上。片手・親指操作を想定し主要アクションは画面下部に配置。

6. データ保存・バックアップ

ストレージ:IndexedDB を主、localStorage は補助。localStorage は同期APIで書き込みが重く、容量が約5MBに制限され、文字列しか保存できないため、メモ・履歴の本体保存には採用しない。

  • IndexedDB:メモ・比較履歴・カテゴリ/タグ定義を保存。非同期で高速、容量が大きく(数百MB以上)、オブジェクトをそのまま保存できる。薄いラッパーライブラリ(idb 等)の利用を想定。
  • localStorage:表示設定(ViewSettings)や最後に開いた画面など、軽量なUI状態のみ。
  • 永続化リクエスト:navigator.storage.persist() を呼び、ブラウザによる自動削除(ストレージ逼迫時のeviction)からデータを保護する。特にiOS Safariは未使用PWAのデータを削除し得るため必須。

エクスポート:JSON を正とする。全データ+スキーマバージョンを1ファイルに書き出す(例:life-supporter-backup-2026-07-05.json)。人間が読め、将来のインポート互換(バージョン判定+マイグレーション)を作りやすい。

  • 受け渡し:Web Share API(navigator.share)でファイル共有シートを開き、AirDrop・LINE・クラウドドライブ等へ直接送れるようにする(非対応環境はダウンロードにフォールバック)。機種変更時は新端末でファイルを選んでインポート。
  • インポート:ファイル選択→スキーマバージョン検証→「置き換え / 追記(マージ)」を選択→取り込み結果を件数で表示。
  • バックアップ促進:最終エクスポートから90日経過などの条件で、設定画面にリマインドを表示。

検討した代替案:QRコード(容量不足)、File System Access API での自動保存(iOS非対応)、クラウド同期(アカウント管理が必要になるため将来拡張へ)。いずれも初期リリースでは JSON+共有シートが最適。

7. データモデル(案)

Memo {
  id, title, category,        // "shopping" | "restaurant" | "place" | "other" | custom
  tags: [string],             // 複数可(例: ["TVで紹介", "カレー"])
  priority,                   // "high" | "normal"
  note?, source?,             // 補足・出典
  done, doneAt?,
  createdAt, updatedAt, sortOrder
}

ViewSettings {                // 表示状態(永続化)
  groupBy,                    // "category" | "tag" | "none"
  sortBy,                     // "createdAt" | "updatedAt" | "manual"
  sortDir                     // "desc" | "asc"
}

Comparison {
  id, name?,                  // 保存名(例: トイレットペーパー)
  unitMode,                   // "per100g" | "per100ml" | "perItem" | "perSheet"
  items: [{ label?, price, amount }],
  savedAt
}
